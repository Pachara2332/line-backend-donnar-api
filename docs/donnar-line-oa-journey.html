Risks · decisions

สิ่งที่ต้องกันตั้งแต่ต้น

Webhook

duplicate events/messages, retry, expired reply token → unique event ID, idempotency, delivery status

Concurrent replies

bot กับ human หรือ staff หลายคนตอบพร้อมกัน → atomic mode switch, version check, owner และ audit trail

LINE failures

API failure, rate limits, user block/unfollow, unknown message type → controlled retry และ fallback

Privacy

กำหนดสิทธิ์ staff, retention ของข้อความ/ไฟล์, ไม่เก็บ secret ใน Git และไม่ log ข้อความส่วนตัวโดยไม่จำเป็น

คำถามก่อนเริ่ม BE

จะใช้ framework/database/hosting อะไร? ใครเป็นพนักงานที่ตอบได้? จะใช้ LINE OA Manager ร่วมกับ inbox ที่สร้างเองอย่างไร? เก็บข้อความและไฟล์นานเท่าไร? ลูกค้าต้องการช่องทางติดต่อกลับแบบไหน?
