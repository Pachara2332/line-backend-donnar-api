Profile

ข้อความหน้าโปรไฟล์

Donnar.Tech | Software House ออกแบบและพัฒนาเว็บไซต์ เว็บแอป ระบบภายใน Dashboard, CRM, Automation และ AI Integration เล่าโจทย์ของธุรกิจคุณให้เราฟัง ทีมงานช่วยคิดแนวทางที่เหมาะกับเป้าหมายและงบประมาณ

Before backend

ข้อความต้อนรับระหว่างเตรียมระบบ

สวัสดีครับ 👋 ยินดีต้อนรับสู่ Donnar.Tech เราช่วยออกแบบและพัฒนาซอฟต์แวร์ให้เหมาะกับโจทย์ธุรกิจของคุณ พิมพ์สั้น ๆ ได้เลยว่าอยากทำระบบอะไร หรือกำลังเจอปัญหาอะไร ทีมงานจะเข้ามาตอบและช่วยคุยรายละเอียดต่อครับ

นี่เป็นข้อความต้อนรับแบบทั่วไป ไม่สัญญาว่ามีบอตหรือ inbox อัตโนมัติขณะ backend ยังไม่พร้อม

After backend · MVP

ข้อความต้อนรับเมื่อ flow ใช้งานจริง

สวัสดีครับ 👋 ยินดีต้อนรับสู่ Donnar.Tech ผมเป็นผู้ช่วยของทีม จะช่วยเก็บโจทย์เบื้องต้นทีละข้อ แล้วส่งต่อให้ทีมดูแลต่อ คุณเลือกหัวข้อด้านล่าง หรือพิมพ์เล่าโจทย์ได้เลย ถ้าอยากคุยกับพนักงาน พิมพ์ “คุยกับคน” ได้ทุกเมื่อครับ

Qualification flow

บอตถามทีละข้อ ไม่กดดันลูกค้า

Stepข้อความที่ลูกค้าเห็นข้อมูลที่เก็บ
1“วันนี้อยากให้เราช่วยเรื่องไหนครับ?” พร้อม service optionsservice, source, lead = NEW
2“ระบบนี้อยากช่วยแก้ปัญหาอะไรเป็นหลักครับ?”problem, lead = QUALIFYING
3“ใครจะเป็นคนใช้งาน และประมาณกี่คนครับ?”users
4“มีฟีเจอร์สำคัญ 2–3 อย่างที่อยากได้ไหมครับ?”features
5“ตอนนี้มีระบบเดิมอยู่แล้ว หรือเริ่มใหม่ครับ?”existingSystem
6“มีช่วงงบประมาณคร่าว ๆ ไหมครับ? ข้ามได้”budgetRange
7“อยากเริ่มใช้ประมาณเมื่อไรครับ? ข้ามได้”timeline
8“มีตัวอย่าง/ลิงก์/ไฟล์ที่อยากให้ทีมดูไหมครับ?”references
9“สะดวกให้ทีมติดต่อกลับทางแชตนี้ หรือช่องทางอื่นครับ?”contactPreference

ทุกขั้นมีปุ่ม “ข้ามก่อน” และ “คุยกับทีม”; หลีกเลี่ยงการขอข้อมูลส่วนตัวเกินจำเป็น

Operational setup checklist

ลำดับตั้งค่าหลัง OA สร้างเสร็จ

  1. ยืนยัน profile, logo, description และเวลาทำการ
  2. เปิด Messaging API ภายใต้ provider Donnar.Tech
  3. เก็บ channel secret/token ใน secret manager ไม่ใส่ Git
  4. ระหว่างยังไม่มี backend ใช้ human chat และ greeting ที่ไม่อ้าง automation; ไม่เปิด Rich Menu จาก OA Manager
  5. เมื่อ backend มี HTTPS webhook แล้ว ตั้ง URL, verify, ทดสอบ follow/text/postback และ signature
  6. สร้าง Rich Menu ผ่าน Messaging API จาก backend แล้วตั้งเป็น default หลังทดสอบ action ครบ
  7. ปิดหรือปรับ greeting/auto-reply ที่อาจตอบซ้อนกับ backend
  8. ทดสอบ BOT → HUMAN → BOT กับบัญชีทดสอบ ก่อนเผยแพร่ QR
